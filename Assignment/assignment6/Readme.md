# 과제 06: 순차 탐색, BST, AVL 트리의 성능 비교

## 1. 실행 환경 및 방법

- 컴파일: `gcc -Wall -Wextra -o hw06 hw06.c` (경고 없음)
- 실행: `./hw06` (seed를 생략하면 time 기반, `./hw06 <seed>`로 지정 가능). 아래 결과는 macOS(ARM64)에서 실행한 한 번의 결과이며 전체 출력은 `Result.txt`에 있음.
- 숫자 비교 횟수는 "노드(또는 배열 원소) 한 개를 방문하여 키와 비교하는 것"을 1회로 계산함. 같음/작음/큼 판단은 한 번의 3분 비교로 보고 1회로 셈. 중복이 발견되어 삽입하지 않은 경우의 비교도 포함하며, AVL의 높이 계산, balance factor 확인, 회전 판단은 포함하지 않음.

## 2. 실험 결과

| 항목                     | 배열    | BST     | AVL    |
| ------------------------ | ------- | ------- | ------ |
| 저장된 서로 다른 값      | 95      | 95      | 95     |
| 생성 과정 비교 횟수      | 4,580   | 589     | 522    |
| 길이 / 높이              | 길이 95 | 높이 11 | 높이 8 |
| 탐색 총 비교 횟수 (50회) | 4,529   | 397     | 333    |
| 탐색 평균 비교 횟수      | 90.58   | 7.94    | 6.66   |

- 100번 생성 중 중복으로 삽입되지 않은 값: 5개 (308이 3번, 174, 601, 307이 각 2번 생성됨)
- 탐색 50개 중 성공 5개(590, 668, 421, 406, 561), 실패 45개. 저장된 값이 0~1,000의 1,001개 후보 중 95개뿐이라 대부분 실패함.

## 3. 분석

### 3.1 BST와 AVL 트리의 높이가 다른 이유

두 트리는 같은 95개 값을 같은 순서로 받았지만 높이가 11과 8로 달랐다. BST는 삽입 순서만으로 모양이 정해지고 균형을 맞추지 않으므로, 비슷한 범위의 값이 연달아 들어오면 한쪽 경로가 계속 길어진다. AVL 트리는 삽입 후 경로를 거슬러 올라가며 왼쪽과 오른쪽 서브트리의 높이 차이가 2가 된 노드에서 LL, RR, LR, RL 회전을 수행해 치우침을 즉시 해소한다. 그 결과 노드 95개로 만들 수 있는 최소 높이 7(2^7 - 1 = 127 >= 95)에 가까운 8이 유지되었다.

### 3.2 높이가 탐색 비교 횟수에 미치는 영향

트리 탐색은 루트에서 한 층 내려갈 때마다 1회 비교하므로, 한 번의 탐색 비교 횟수는 그 경로의 길이이고 최대값은 트리의 높이이다. 실제로 BST 탐색의 최대 비교 횟수는 11회(393, 126, 84 등), AVL은 8회(919)로 각 트리의 높이와 같았다.

평균은 BST 7.94회, AVL 6.66회로 AVL이 약 16% 적었다. 높이 차이는 3이지만 평균 차이는 약 1.3회에 그쳤는데, 높이는 가장 깊은 한 경로만 나타내고 BST의 대부분 경로는 그보다 짧기 때문이다. 또한 키 13, 612, 624는 BST에서 4회, AVL에서 6회로 오히려 BST가 적었다. BST에서 우연히 얕은 쪽에 놓인 값이라면 더 빨리 찾을 수 있다는 뜻이다. 즉 AVL의 장점은 개별 탐색이 항상 빠른 것이 아니라 가장 나쁜 경우를 높이 8 이하로 제한하여 평균과 최악을 함께 낮추는 데 있다.

순차 탐색은 실패한 45번 모두 95개 전체를 비교했고 평균 90.58회로 BST보다 약 11배 많았다.

### 3.3 생성 비용과 탐색 비용 비교

- 배열: 값이 들어올 때마다 처음부터 끝까지 중복 확인을 하므로 생성 비교가 4,580회로 가장 많다. 저장 개수가 늘수록 한 번의 확인 비용도 커져 전체가 약 n^2/2 규모로 늘어난다(95^2/2 ≈ 4,500과 비슷함).
- BST: 삽입마다 경로 길이만큼만 비교하므로 589회로 배열의 약 13%이다.
- AVL: 522회로 가장 적다. 삽입 경로가 짧게 유지되기 때문이다. 다만 이 수치에는 회전과 높이 갱신 비용이 빠져 있으므로 실제 실행 시간까지 고려하면 BST와의 차이는 더 줄어들 수 있다.
- 탐색: 총 비교 횟수는 AVL(333) < BST(397) < 순차(4,529) 순서이다. 데이터가 많아질수록 순차 탐색은 O(n), AVL은 O(log n)으로 차이가 더 커진다.

### 3.4 한계

한 번의 무작위 실행 결과이다. 무작위 순서로 삽입하면 BST도 평균적으로 O(log n)에 가까운 높이를 가지므로, 이번처럼 BST와 AVL의 차이가 크지 않을 수 있다. 입력이 정렬되어 있거나 거의 정렬된 경우에는 BST의 높이가 n까지 커질 수 있어 AVL의 장점이 훨씬 크게 드러날 것이다.
