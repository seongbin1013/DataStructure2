# 과제 07: 인접 행렬과 인접 리스트의 성능 비교

## 1. 실행 방법

```
gcc -Wall -Wextra -o Graph Graph.c
./Graph          # 기본 seed(20261017) -> 결과 재현 가능
./Graph 1        # seed를 바꿔서 다른 그래프로 실험
```

- 정점 100개(0~99), 무방향 단순 그래프(자기 자신 연결 X, 중복 간선 X)
- 난수는 플랫폼마다 결과가 달라지는 `rand()` 대신 직접 구현한 xorshift32를 사용함. 그래서 macOS와 Linux 어디서 실행해도 같은 seed에서 같은 결과가 나옴
- 희소 그래프(간선 100개)와 밀집 그래프(간선 4,000개)를 각각 한 번 랜덤 생성하고, 같은 간선 집합으로 인접 행렬과 인접 리스트를 모두 만듦
- 프로그램은 두 표현이 같은 그래프인지(대칭성, 자기 루프 없음, 리스트 노드 중복 없음, 간선 수 일치) 검사한 뒤에 측정함. 연산 후에도 다시 검사함
- 한 사이클의 연산(삽입 1회, 삭제 1회, 연결 확인 1회, 인접 정점 1회)은 두 표현에 완전히 같은 정점 쌍과 같은 정점으로 수행함

## 2. 비교 횟수 기준

| 연산             | 인접 행렬                   | 인접 리스트                                                                  |
| ---------------- | --------------------------- | ---------------------------------------------------------------------------- |
| 연결 확인 (u, v) | matrix[u][v] 확인 1회       | u의 리스트 노드를 하나씩 확인한 횟수                                         |
| 삽입 (u, v)      | 중복 확인 matrix[u][v] 1회  | u의 리스트에서 v가 있는지 끝까지 확인한 횟수 (없는 간선이므로 u의 차수 전체) |
| 삭제 (u, v)      | 존재 확인 matrix[u][v] 1회  | u의 리스트에서 v를 찾을 때까지 + v의 리스트에서 u를 찾을 때까지 확인한 횟수  |
| 인접 정점 출력 w | matrix[w][0..99] 확인 100회 | w의 리스트 노드를 모두 확인한 횟수 (= w의 차수)                              |

- 리스트에 삽입할 때는 맨 앞에 붙이므로(push front) 위치를 찾는 비용은 없고, 비교는 중복 확인에서만 발생함
- 메모리는 `sizeof`로 계산한 자료구조 크기임. 행렬은 `sizeof(MatGraph)`이고, 리스트는 `sizeof(ListGraph)`(정점별 head 배열과 관리용 필드) + (노드 수 x `sizeof(Node)`)임. 난수 생성용 임시 배열(`Truth`)은 제외함
- 리스트 노드는 `malloc`으로 하나씩 할당하므로, 실제 프로세스 메모리에는 할당기가 블록마다 붙이는 관리 정보가 더 들어감. 이 값은 할당기마다 달라서 포함하지 않았고, 따라서 리스트 메모리 수치는 실제 사용량보다 작거나 같은 추정값임 (행렬은 한 번에 할당하므로 이 차이가 거의 없음)

## 3. 실행 결과 (seed = 20261017)

선택된 연산 대상: 희소 그래프는 삽입 (8,72), 삭제 (94,50), 연결 확인 (2,87), 인접 정점 2번이고, 밀집 그래프는 삽입 (77,27), 삭제 (27,70), 연결 확인 (30,12), 인접 정점 62번임.

연결 확인 결과는 두 쌍 모두 연결 안 됨(NO)이었고, 두 표현의 판정이 같았음.

- 희소 (2,87): 정점 2의 이웃은 75 하나뿐이라, 리스트는 노드 1개를 확인하고 끝까지 가서 없음을 판정함. 그래서 연결되지 않았는데도 행렬과 같은 1회가 나옴. 리스트가 빨랐던 것이 아니라 정점 2의 차수가 1이었기 때문임
- 밀집 (30,12): 연결되지 않은 쌍이라 리스트는 정점 30의 리스트 전체(77개 노드)를 확인함

| Case | 그래프 - 표현   | Memory (Bytes, sizeof 계산값) | 삽입 | 삭제 | 연결 확인 | 인접 정점 |
| ---- | --------------- | ----------------------------- | ---- | ---- | --------- | --------- |
| 1    | Sparse - Matrix | 40,008                        | 1    | 1    | 1         | 100       |
| 2    | Sparse - List   | 4,016                         | 3    | 3    | 1         | 1         |
| 3    | Dense - Matrix  | 40,008                        | 1    | 1    | 1         | 100       |
| 4    | Dense - List    | 128,816                       | 82   | 141  | 77        | 77        |

메모리 계산식 (이 환경: int 4바이트, 포인터 8바이트, Node 16바이트):

- 행렬: 100 x 100 x 4 = 40,000 + 관리 필드 8 = 40,008 바이트. 간선 수와 무관함
- 리스트: 816 (head 배열 + 관리 필드) + 노드 수 x 16. 희소는 200개 노드이므로 816 + 3,200 = 4,016, 밀집은 8,000개 노드이므로 816 + 128,000 = 128,816. 무방향이라 간선 1개당 노드가 2개 생김

### 보충 실험 (과제 필수 출력 아님)

한 번의 연산은 선택된 정점에 따라 결과가 크게 달라지므로, 같은 그래프에서 무작위 연산을 1,000번 반복한 평균도 추가로 측정함 (삽입 후와 삭제 후에는 원래 상태로 되돌림). 연결 확인은 무작위 쌍(Connect) 외에 연결된 쌍만(Conn(Y))과 연결 안 된 쌍만(Conn(N))으로 나눠 각각 1,000번 측정함. 무작위 쌍은 그래프 밀도만큼 연결된 쌍이 섞여 있어서, 이 둘을 나누지 않으면 평균값을 해석하기 어렵기 때문임.

| 그래프 | 표현   | 삽입  | 삭제  | Connect | Conn(Y) | Conn(N) | 인접 정점 |
| ------ | ------ | ----- | ----- | ------- | ------- | ------- | --------- |
| Sparse | Matrix | 1.00  | 1.00  | 1.00    | 1.00    | 1.00    | 100.00    |
| Sparse | List   | 2.00  | 4.25  | 1.93    | 2.03    | 2.00    | 2.04      |
| Dense  | Matrix | 1.00  | 1.00  | 1.00    | 1.00    | 1.00    | 100.00    |
| Dense  | List   | 79.45 | 82.95 | 47.23   | 40.72   | 79.25   | 80.29     |

seed를 1로 바꿔도 같은 경향이었음 (Dense List 삽입 79.19, 삭제 81.82, Connect 48.29, Conn(Y) 40.79, Conn(N) 79.53, 인접 정점 80.22).

## 4. 분석

### 4.1 희소 그래프 (V = 100, E = 100)

- 메모리: 행렬은 40,008 바이트인데 리스트는 4,016 바이트로, 리스트가 약 10분의 1임. 정점 100개의 최대 간선 수는 4,950개인데 실제 간선은 100개(밀도 약 2%)뿐이라서, 행렬의 10,000칸 중 대부분이 0이고 이 낭비가 그대로 메모리 차이로 나타남
- 인접 정점 출력: 행렬은 항상 100회인데 리스트는 평균 2회(해당 정점의 차수)였음. 정점당 평균 차수가 약 2라서, 리스트는 실제 이웃만 보면 되지만 행렬은 이웃이 없는 칸도 전부 봐야 함. 이 연산에서 리스트가 가장 크게 유리했음
- 연결 확인, 삽입, 삭제: 행렬은 항상 1회임. 리스트는 평균 2~4회로 행렬보다 조금 많지만, 리스트 길이가 짧아서 그 차이는 거의 무시할 만함
- 정리하면 희소 그래프에서는 리스트가 메모리와 인접 정점 탐색에서 크게 이기고, 행렬의 장점인 O(1) 연산은 리스트의 짧은 리스트 덕분에 거의 의미가 없어짐

### 4.2 밀집 그래프 (V = 100, E = 4,000)

- 메모리: 행렬은 그대로 40,008 바이트이고, 리스트는 128,816 바이트로 약 3.2배 더 큼. 최대 간선 수 4,950개 중 4,000개가 있으므로 밀도가 약 81%이고, 행렬의 칸은 대부분 의미 있는 정보를 담게 됨. 반면 리스트는 간선마다 노드 2개를 만들고 노드마다 포인터(8바이트)와 정렬 padding이 붙어서 간선 정보 하나당 비용이 행렬보다 훨씬 큼
- 연결 확인, 삽입, 삭제: 행렬은 여전히 1회임. 리스트는 평균 차수가 약 80이라서 삽입은 평균 79회(없는 간선이라 u의 리스트 전체를 확인), 삭제는 평균 83회(위 단일 실행은 u 쪽과 v 쪽 리스트를 모두 탐색해 141회), 연결 확인은 평균 47회였음. 연결 확인을 나눠 보면 연결된 쌍은 평균 40.7회로 차수(약 80)의 절반 정도에서 찾고 멈추고, 연결 안 된 쌍은 평균 79.3회로 리스트 끝까지 확인함. 무작위 쌍이 연결돼 있을 확률은 밀도와 같은 약 81%이므로 0.81 x 40.7 + 0.19 x 79.3 = 약 48회가 되고, 이 값이 측정한 47.2회와 거의 같음. 반면 행렬은 연결 여부와 상관없이 항상 1회임
- 인접 정점 출력: 행렬은 100회, 리스트는 평균 80회로 차이가 거의 없어짐. 희소 그래프에서 100회 대 2회였던 큰 격차가 사라진 것은 정점의 이웃이 대부분의 칸을 채우기 때문임
- 정리하면 밀집 그래프에서는 행렬이 메모리도 더 작고 대부분의 연산이 더 빠르며, 리스트가 유리한 점은 인접 정점 출력에서 약간 적은 비교 횟수뿐이었음

### 4.3 어떤 경우에 무엇을 쓰는 것이 적절한가

두 표현의 비용은 간선 수 E에 대해 이렇게 달라짐: 행렬 메모리는 V^2으로 고정이고, 리스트 메모리는 V + E에 비례함. 이 실험 환경에서는 노드 하나가 16바이트이므로 리스트가 행렬보다 커지는 지점은 약 816 + 32E > 40,000, 즉 E > 약 1,225개임. 정점 100개의 최대 간선 수가 4,950개이므로 밀도 약 25%가 메모리 손익분기점이고, 실험한 희소(2%)는 이보다 훨씬 아래, 밀집(81%)은 훨씬 위에 있었음.

| 상황                                  | 적합한 표현             | 이유                                                 |
| ------------------------------------- | ----------------------- | ---------------------------------------------------- |
| 간선이 적은 희소 그래프 (E가 V 정도)  | 인접 리스트             | 메모리가 10배 작고, 인접 정점 탐색이 차수만큼만 걸림 |
| 간선이 많은 밀집 그래프               | 인접 행렬               | 메모리가 더 작고, 연결 확인과 삽입, 삭제가 항상 1회  |
| 두 정점의 연결 여부를 자주 확인함     | 인접 행렬               | O(1). 리스트는 차수에 비례함                         |
| 모든 이웃을 자주 순회함 (BFS, DFS 등) | 인접 리스트 (희소일 때) | 행렬은 정점마다 V칸을 봐야 함                        |
| 정점 수가 매우 큼                     | 인접 리스트 (희소일 때) | V^2 메모리를 감당하기 어려움                         |

### 4.4 한계와 느낀 점

- 이 실험은 정점이 100개뿐이라 절대적인 수치는 작음. 하지만 행렬은 V^2, 리스트는 V + E로 증가한다는 점이 수치에서 그대로 확인되어서, 정점이 커질수록 희소 그래프에서 행렬의 낭비가 더 심해질 것임
- 단일 실행의 비교 횟수는 선택된 정점 쌍에 따라 크게 달라지므로(예: 밀집 리스트 삭제 141회), 평균값 표를 함께 두어서 경향을 확인함
- 리스트 메모리는 노드 하나의 크기(여기서는 padding 포함 16바이트)에 크게 좌우됨. 또 `sizeof` 계산에는 `malloc`의 블록 관리 비용이 빠져 있어서 실제 리스트 메모리는 이보다 더 큼. 따라서 실제 손익분기점은 25%보다 조금 더 낮은 밀도에서 생길 것이고, 환경이 달라지면 이 지점도 달라질 수 있음
- 단일 실행의 연결 확인 1회(희소)는 리스트가 행렬만큼 빨랐다는 뜻이 아니라, 선택된 정점의 차수가 1이었기 때문임. 그래서 연결된 쌍과 연결 안 된 쌍을 나눈 보충 측정을 추가함
