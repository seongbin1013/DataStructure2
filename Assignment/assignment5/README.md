# 과제 05: 순차 탐색과 이진 탐색 트리 탐색의 비교

(시드 1791195547 실행 결과 기준: 데이터 100개, 탐색 키 50개. 키별 탐색 결과와 전체 출력은 `result_seed1791195547.txt` 참고. 재현: `gcc hw05.c -o hw05 && ./hw05 1791195547`)

## 1. 순차 탐색의 총 및 평균 비교 횟수

| 총 비교 횟수 | 평균 비교 횟수 |
| -----------: | -------------: |
|        4,822 |          96.44 |

- 비교 횟수는 `arr[i] == key`를 실행할 때마다 1회로 셈.
- 탐색 키 50개 중 성공 4회, 실패 46회였음. 실패하면 배열 100개를 모두 비교하므로 실패 46회가 4,600회(46 x 100)를 차지하고, 성공 4회의 합계는 222회(16 + 17 + 91 + 98)였음.

## 2. 이진 탐색 트리 탐색의 총 및 평균 비교 횟수

| 총 비교 횟수 | 평균 비교 횟수 |
| -----------: | -------------: |
|          746 |          14.92 |

- 비교 횟수는 `bstSearch`에서 실행된 `==`와 `<`를 각각 1회로 셈. 노드가 일치하지 않으면 2회, 일치하면 1회임.
- 방문한 노드는 총 375개(평균 7.50개)였고, 일치하지 않은 노드마다 2회씩 세어져 비교 횟수는 방문 노드 수의 약 2배가 되었음.
- 한 번의 탐색에서 최대 22회(노드 11개)까지 비교했음.

## 3. BST를 생성하는 과정에서 발생한 비교 횟수

**641회** (최종 트리 높이 12)

- BST 삽입에서는 노드마다 실행된 `<` 비교를 1회로 셈. 값이 모두 서로 다르므로 `==` 비교는 하지 않으며, 루트는 비교 대상이 없어 0회임.
- 100개를 삽입하는 동안 삽입 1회당 평균 약 6.4회를 비교했음. 새 노드는 자신의 부모 위치까지 내려가며 비교하기 때문에, 트리가 깊어질수록 삽입 비용도 커졌음.
- 배열은 발생 순서대로 저장만 하므로 생성 비교가 0회임.

## 4. 두 탐색 방법의 성능 차이에 대한 분석

BST 탐색의 평균 비교 횟수(14.92)가 순차 탐색(96.44)보다 약 6.5배 적었음. 왜냐하면 순차 탐색은 비교 한 번에 후보를 1개만 제거하지만, BST는 노드 하나를 비교할 때마다 왼쪽 또는 오른쪽 서브트리로 후보를 크게 줄이기 때문임. 순차 탐색은 O(n), 균형에 가까운 BST는 O(log n)에 해당함.

탐색 키 50개 중 46개가 실패였음. 0~1,000 범위에서 100개만 저장했으므로 임의의 키가 존재할 확률이 약 10%라서 이렇게 나옴. 순차 탐색은 실패하면 항상 100회를 모두 비교하므로 평균이 100에 가까워졌음. 반면 BST는 실패해도 리프까지만 내려가므로 실패 평균이 약 15.0회였음. 키가 자주 존재하는 경우라면 순차 탐색 평균이 약 n/2 = 50회로 줄어 차이는 작아질 것임.

BST는 노드당 비교가 2회라서 방문한 노드 수(평균 7.50개)의 약 2배가 비교 횟수로 잡혔음. 그래도 순차 탐색의 약 100회에 비하면 훨씬 적었음.

## 5. BST 생성 비용을 고려했을 때의 성능 차이에 대한 분석

배열은 비교 없이 저장만 하면 되지만, BST는 만들 때 641회의 비교가 필요했음. 그래도 생성 비용을 포함한 BST 총합은 641 + 746 = 1,387회로, 순차 탐색 총합 4,822회보다 3,435회 적었음 (약 3.5배). 이 값은 50회 탐색에서 실제로 측정한 결과임.

손익분기점은 측정값이 아니라 추정치임. 이번 50회 탐색에서 탐색 1회당 평균 81.52회(96.44 - 14.92)를 절약했고, 이 절감량이 이후 탐색에서도 같다고 가정하면 641 / 81.52 = 7.86, 즉 약 8회 안팎의 탐색이면 생성 비용을 회수한다고 볼 수 있음. 다만 절감량은 키의 성공/실패 비율과 트리 모양에 따라 달라짐. 이번 키는 대부분 실패여서 순차 탐색이 불리했으므로, 키가 자주 존재하면 절감량이 줄어 손익분기 횟수는 더 커짐.

탐색을 한두 번만 하고 끝나는 경우에는 생성 비용 때문에 배열 순차 탐색이 더 유리함. BST는 같은 데이터를 여러 번 탐색할 때 의미가 있는 구조임.

## 6. 이진 탐색 트리의 구조에 따른 탐색 성능 변화에 대한 분석

BST의 탐색 비용은 탐색 경로의 길이, 즉 노드의 깊이에 의해 결정됨. 이번 트리는 랜덤 순서로 삽입해서 높이가 12였고, 100개 노드로 만들 수 있는 가장 낮은 트리(높이 7)의 약 1.7배였음. 그래서 한 번의 탐색에서 최대 11개 노드를 거쳐 비교가 22회까지 나왔음. 평균은 14.92회라 여전히 순차 탐색보다 훨씬 적었음.

같은 100개 값이라도 삽입 순서에 따라 트리 모양이 달라짐. 시드를 바꿔 여러 번 실행했을 때 BST 생성 비교 횟수는 583~786회, 트리 높이는 12~14로 달랐음 (이번 실행은 641회, 높이 12).

최악의 경우는 값이 정렬된 순서로 들어올 때임. 모든 노드가 한쪽으로만 연결되어 연결 리스트처럼 되고 (높이 100), 이론상 생성 비교는 0 + 1 + ... + 99 = 4,950회가 됨. 탐색도 한 번에 최대 약 200회(노드 100개 x 2회)까지 늘어나 순차 탐색의 최대 100회보다 많아질 수 있음 (직접 실행한 값이 아니라 계산한 값임). 따라서 BST의 성능은 삽입 순서와 트리의 균형에 크게 의존하며, 이를 보완하려면 AVL 트리나 레드-블랙 트리 같은 균형 이진 탐색 트리가 필요함.
