# 과제 11: 삽입 정렬과 쉘 정렬의 성능 비교

## 1. 실험 방법

- 데이터: `rand() % 100000`으로 만든 무작위 정수 (시드는 `time(NULL)`)
- 크기: n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- 각 크기마다 원본 배열을 한 번 만들고, 세 정렬 모두 `memcpy`로 복사한 같은 데이터를 오름차순 정렬
- 비교 횟수: `a[j] > key`처럼 **데이터 값끼리 비교한 횟수만** 셈 (인덱스 검사 `j >= 0`, 데이터 생성·복사는 제외)
- 정렬 후 `isSorted()`로 오름차순 여부를 확인

| 방법               | 간격 수열                                       |
| ------------------ | ----------------------------------------------- |
| 삽입 정렬          | 1                                               |
| 쉘 정렬 (Original) | n/2, n/4, ..., 1                                |
| 쉘 정렬 (Knuth)    | n보다 작은 가장 큰 h부터 역순 적용 (h = 3h + 1) |

세 방법 모두 같은 `gapInsertionSort(a, n, gap, &cmp)` 함수를 사용한다. 쉘 정렬은 간격 단위 삽입 정렬을 반복하며, gap = 1이면 일반 삽입 정렬과 같다. 따라서 세 방법의 차이는 간격 수열뿐이다.

**보조 실험** (`Passanalysis.c`, 제출 프로그램과 별개): 쉘 정렬을 **단계별로** 분석하기 위해 시드를 고정한 데이터로 각 단계의 비교 횟수와 단계 후 남은 **역순쌍 수**를 측정했다. 역순쌍은 i < j인데 a[i] > a[j]인 쌍으로, 0이면 정렬이 끝난 것이다. 따라서 "그 단계에서 줄어든 역순쌍 수"를 그 단계의 정렬 효과로 본다. 또 시드 1~30으로 반복 실험했다. 보조 실험 수치는 Linux(glibc `rand()`) 환경에서 측정한 값이며, 운영체제에 따라 같은 시드라도 값이 다를 수 있다.

## 3. 분석

각 절은 **[측정]** 실험으로 확인한 사실, **[해석]** 측정값에서 끌어낸 설명, **[이론]** 알려진 이론(이번 실험으로 검증하지 않음)으로 구분한다.

### 3.1 데이터 크기 증가에 따른 비교 횟수 변화

| n 변화         | Insertion | Original |  Knuth |
| -------------- | --------: | -------: | -----: |
| 1,000 → 2,000  |    4.06배 |   2.28배 | 2.38배 |
| 2,000 → 4,000  |    3.88배 |   2.33배 | 2.25배 |
| 4,000 → 8,000  |    4.03배 |   2.34배 | 2.27배 |
| 8,000 → 16,000 |    3.98배 |   2.41배 | 2.59배 |

**[측정]** n이 2배가 될 때 삽입 정렬은 3.88~4.06배, 쉘 정렬은 2.25~2.59배 증가했다.

**[해석]** 삽입 정렬에서 원소를 한 칸 옮길 때마다 비교 1회가 들고 역순쌍이 정확히 1개 줄어든다. 여기에 원소마다 멈추는 비교가 1회씩 더해지므로 비교 횟수 = (n − 1 − 맨 앞까지 이동한 원소 수) + 역순쌍 수, 즉 약 (n − 1) + 역순쌍 수다. 보조 실험의 n = 20,000 데이터는 처음 역순쌍이 99,861,784개였고, 2절의 삽입 정렬 비교 횟수(99,500,795)도 같은 크기다.

**[이론]** 무작위 데이터의 평균 역순쌍 수는 n(n−1)/4이므로 삽입 정렬의 평균 비교 횟수는 약 n²/4, 즉 O(n²)이다. n이 2배면 4배가 되며, 측정값(n = 1,000: 252,305 ≈ 250,000)이 이와 일치한다. 쉘 정렬의 증가율은 측정한 6개 크기만으로 확정할 수 없으므로, 삽입 정렬보다 증가 폭이 훨씬 작다는 점까지만 결론으로 삼는다.

### 3.2 삽입 정렬과 쉘 정렬의 성능 차이

|      n | Insertion ÷ Original | Insertion ÷ Knuth |
| -----: | -------------------: | ----------------: |
|  1,000 |              약 16배 |           약 18배 |
|  4,000 |              약 47배 |           약 52배 |
|  8,000 |              약 81배 |           약 92배 |
| 20,000 |             약 162배 |          약 188배 |

**[측정]** n이 커질수록 격차가 벌어졌다 (16배 → 162~188배). 보조 실험(n = 20,000)에서 쉘 정렬의 마지막 gap 1 단계는 Original 30,306회, Knuth 54,046회만 비교했다. 같은 gap 1 정렬이라도 삽입 정렬은 약 1억 회를 비교한다.

**[해석]** 둘 다 결국 역순쌍 약 1억 개를 모두 없애야 한다. 삽입 정렬은 한 번 이동에 역순쌍을 1개만 줄이므로 비교 횟수가 역순쌍 수만큼 필요하다. 쉘 정렬은 큰 간격 단계에서 원소를 h칸씩 옮기므로 한 번 이동에 여러 역순쌍이 줄어든다. 예를 들어 Original의 첫 단계(gap 10000)는 비교 10,000회로 역순쌍을 약 3,270만 개 줄였다. 그래서 gap 1 단계에 도착했을 때 남은 역순쌍은 Original 10,308개, Knuth 34,048개뿐이었다. 이때 gap 1 단계의 비교 횟수는 "멈춤 비교 + 남은 역순쌍 수"와 정확히 일치했다 (Original: 19,998 + 10,308 = 30,306, Knuth: 19,998 + 34,048 = 54,046). 멈춤 비교가 n − 1 = 19,999보다 1 적은 것은, 배열 맨 앞까지 이동한 원소 1개가 멈춤 비교 없이 반복을 끝냈기 때문이다.

### 3.4 간격 수열이 쉘 정렬의 성능에 영향을 미치는 이유

#### (1) 비교 횟수의 구성 [측정]

간격 h 단계에서는 원소 (n − h)개가 이동 여부와 관계없이 최소 1번씩 비교된다. 따라서 비교 횟수 = **최소 비교 Σ(n − h)** + **추가 비교**(실제 이동 때문에 생기는 비교)로 나눌 수 있다. 2절 실행값을 이렇게 나눈 결과는 다음과 같다.

|      n | 단계 수 (O / K) | 최소 비교 (O / K) | 추가 비교 (O / K) |
| -----: | --------------: | ----------------: | ----------------: |
|  1,000 |           9 / 6 |     8,006 / 5,457 |     7,921 / 8,849 |
|  4,000 |          11 / 8 |   40,006 / 27,084 |   44,559 / 49,611 |
| 16,000 |          13 / 9 | 192,006 / 129,243 | 285,482 / 321,632 |
| 20,000 |          14 / 9 | 260,005 / 165,243 | 353,797 / 363,879 |

Knuth는 단계가 적어 최소 비교가 크게 적고, 추가 비교는 Original과 비슷하거나 조금 많았다.

#### (2) 단계 수만으로는 설명되지 않는다 [해석]

단계 수가 적을수록 무조건 유리하다면 단계가 1개뿐인 삽입 정렬이 가장 빨라야 한다. 하지만 삽입 정렬은 최소 비교가 19,999회로 가장 적은데도 추가 비교가 약 1억 회였다. 즉 단계를 줄이면 남은 단계가 정렬을 더 많이 떠맡아야 하고, **각 단계의 정렬 효과가 충분히 크지 않으면 추가 비교가 폭증한다.** 따라서 Knuth가 적은 이유는 "단계를 줄이면서도 추가 비교가 늘지 않았기 때문"이며, 그 이유를 단계별 측정으로 확인했다.

#### (4) 해석 [해석]

- **Knuth는 단계당 정렬 효과가 크다.** 처음 3단계만으로 역순쌍을 14.4%까지 줄였다. Original은 5단계를 써도 16.4%가 남았고, 이 지점까지 비교도 약 4만 회 더 들었다. Knuth는 간격이 약 1/3씩 줄어서 단계마다 그룹 크기가 약 3배씩 커지므로, 한 단계에서 정리하는 범위가 넓다.
- **Original에서는 비교 대비 효과가 낮은 단계가 반복된다.** 간격이 1/2씩만 줄어서 단계 수가 많고, 각 단계에 최소 비교 약 n회가 고정으로 든다. 특히 gap 19 단계 이후 남은 역순쌍은 약 50만 개뿐이었다. 그런데도 마지막 4단계(gap 9, 4, 2, 1)에서 비교가 186,247회나 들었고, 이 중 79,984회는 이동과 무관한 최소 비교였다.
- **결국 성능은 "단계 수(고정 비용)"와 "단계별 정렬 효과(추가 비용)"의 균형으로 정해진다.** Knuth는 단계를 줄이면서도 각 단계의 정렬 효과가 커서 추가 비교가 Original 수준에 머물렀다. 그 결과 최소 비교를 아낀 만큼 전체 비교가 줄었다.

#### (5) 간격 구성에 관한 이론 [이론]

- **수학적 사실**: Original 간격은 다음 간격이 이전 간격의 절반이라 공약수를 갖는 경우가 많다 (예: 10000과 5000). 인접한 Knuth 간격 h와 3h + 1은 gcd(h, 3h+1) = gcd(h, 1) = 1이므로 항상 서로소다.
- **성능에 대한 추론**: 다음 간격이 이전 간격의 약수이면, 앞 단계에서 같은 그룹이던 원소들이 다음 단계에서도 같은 그룹에 묶인다. 그래서 서로 다른 그룹의 원소가 섞이는 시점이 늦어질 수 있다. 서로소인 간격은 이런 겹침을 피한다. 다만 **서로소라는 사실 자체가 성능 향상을 증명하지는 않으며**, 이번 실험에서도 성능 차이를 가장 직접적으로 설명한 것은 (3)의 단계 수와 단계별 정렬 효과였다.
- **알려진 결과**: n이 2의 거듭제곱일 때 Original 간격은 gap 1 직전까지 모두 짝수여서 최악의 경우 O(n²)이 될 수 있다. Knuth 수열의 최악 시간은 O(n^1.5)로 알려져 있다. 이번 실험의 n은 2의 거듭제곱이 아니고 무작위 데이터만 사용했으므로 최악의 경우는 검증하지 않았다.

## 4. 결론

1. **[측정]** 삽입 정렬의 비교 횟수는 n이 2배일 때 약 4배가 되었다. 비교 횟수가 데이터의 역순쌍 수와 거의 같기 때문이며, 이론적인 평균 O(n²)과 일치한다.
2. **[측정]** 쉘 정렬은 큰 간격으로 한 번에 많은 역순쌍을 줄여, 마지막 gap 1 단계를 거의 정렬된 배열에서 수행한다. n = 20,000에서 삽입 정렬보다 약 160~190배 적게 비교했다.
3. **[측정]** Knuth 수열은 무작위 데이터에서 평균 약 9~14% 적게 비교했지만, 항상 더 적지는 않았다 (180번 중 179번).
4. **[해석]** 간격 수열은 단계 수(단계마다 약 n회의 고정 비교)와 단계별 정렬 효과를 함께 결정한다. Knuth는 단계 수가 적으면서도 단계당 정렬 효과가 커서 추가 비교가 늘지 않았고, 이것이 성능 차이의 원인이다.
