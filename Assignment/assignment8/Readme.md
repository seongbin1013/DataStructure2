# 과제 08: 최소 비용 신장 트리(MST) 알고리즘 비교

정점이 50개인 가중치 무방향 연결 그래프를 희소(간선 100개)와 밀집(간선 600개) 두 종류로 생성함. 4가지 경우에 대해 메모리 사용량과 실행시간을 비교함.

| Case | 그래프               | 표현 방법   | 알고리즘 |
| ---- | -------------------- | ----------- | -------- |
| 1    | Sparse (V=50, E=100) | 인접 리스트 | Kruskal  |
| 2    | Dense (V=50, E=600)  | 인접 리스트 | Kruskal  |
| 3    | Sparse (V=50, E=100) | 인접 행렬   | Prim     |
| 4    | Dense (V=50, E=600)  | 인접 행렬   | Prim     |

Case 1과 3, Case 2와 4는 각각 정점, 간선, 가중치가 같은 그래프를 사용함. 표현 방법과 알고리즘만 다름.

## 1. 빌드 및 실행

```bash
gcc Mst.c -o Mst
./Mst                    # 시드를 현재 시각으로 사용
./Mst 1792215850         # 시드 고정 (이 README와 같은 그래프)
./Mst 1792215850 10000   # 두 번째 인자: 시간 측정 반복 횟수 (기본값 10000)
```

- 실행 환경은 macOS (ARM64)이고, 최적화 옵션 없이 빌드함.
- 결과는 `./Mst`를 실행해 얻은 `Output.txt`의 값임 (seed 1792215850). 같은 시드를 주면 같은 그래프가 생성됨.

## 2. 구현 요약

- **그래프 생성**
  - 정점은 0~49, 가중치는 1~1000 사이의 정수임. 자기 자신을 잇는 간선과 중복 간선은 만들지 않음.
  - 먼저 신장 트리 간선 49개를 만들고, 나머지 간선을 무작위로 채움.
  - DFS로 연결 그래프인지 확인하고, 아니면 다시 생성함.
- **Kruskal (인접 리스트)**
  1. 인접 리스트에서 간선을 모음 (u < v인 것만).
  2. 가중치 오름차순으로 힙 정렬함.
  3. Union-Find(경로 압축 + 랭크)로 사이클을 검사하며 간선을 추가함.
  4. 간선이 49개가 되면 종료함.
- **Prim (인접 행렬)**
  - 정점 0에서 시작함.
  - `key[]`(최소 연결 비용), `parent[]`, `visited[]`를 사용함.
  - 매 단계 선형 탐색으로 key가 가장 작은 정점을 선택하므로 O(V²)임.
- **메모리 측정**
  - sizeof 기준으로 할당한 바이트 수를 합산함.
  - 포함: 그래프 표현, 알고리즘 보조 자료구조, MST 결과 배열 (49 x 12 = 588 Bytes)
  - 제외: 난수 생성, 연결성 검사, 출력용 임시 메모리
  - 구조체 크기는 `AdjNode` 16 Bytes, `Edge` 12 Bytes임.
- **실행시간 측정**
  - 그래프 생성 후 MST 계산만 10000회 반복해 1회 평균을 구함. 이 측정을 5번 해서 중앙값을 사용함.
  - 반복하는 이유는 1회 계산이 마이크로초 단위라 한 번만 재면 오차가 크기 때문임.
  - 그래프 생성과 출력은 시간에서 제외하고, 4가지 경우 모두 ms 단위를 사용함.

## 3. 실행 결과

### 3-1. MST 결과

| Case                              | MST 간선 수 | MST 전체 비용 |
| --------------------------------- | ----------- | ------------- |
| 1. Sparse / 인접 리스트 / Kruskal | 49          | 10556         |
| 2. Dense / 인접 리스트 / Kruskal  | 49          | 2249          |
| 3. Sparse / 인접 행렬 / Prim      | 49          | 10556         |
| 4. Dense / 인접 행렬 / Prim       | 49          | 2249          |

- 모든 경우에 MST 간선이 49개임.
- 같은 그래프에서 Kruskal과 Prim의 비용이 일치함.
- 간선 선택 순서는 다름. Kruskal은 가중치 순으로, Prim은 정점 0에서부터 트리를 키우며 고르기 때문임.
- 이번 시드에서는 선택된 간선 집합 자체는 같았음. 전체 간선 목록은 `Output.txt`에 있음.

### 3-2. 메모리 사용량 (Bytes)

| Case                       | 그래프 표현 | 알고리즘 보조 | MST 결과 | 합계      |
| -------------------------- | ----------- | ------------- | -------- | --------- |
| 1. Sparse / List / Kruskal | 3600        | 1600          | 588      | **5788**  |
| 2. Dense / List / Kruskal  | 19600       | 7600          | 588      | **27788** |
| 3. Sparse / Matrix / Prim  | 10000       | 450           | 588      | **11038** |
| 4. Dense / Matrix / Prim   | 10000       | 450           | 588      | **11038** |

계산식:

- 인접 리스트 = 헤드 포인터 50 x 8 + 노드 2E x 16. 무방향이라 간선 1개당 노드가 2개임.
- 인접 행렬 = 50 x 50 x 4 = 10000
- Kruskal 보조 = 간선 배열 E x 12 + parent, rank 50 x 4 x 2
- Prim 보조 = key, parent 50 x 4 x 2 + visited 50 x 1 = 450

### 3-3. 실행시간 (ms)

| Case                       | 실행시간 |
| -------------------------- | -------- |
| 1. Sparse / List / Kruskal | 0.003502 |
| 2. Dense / List / Kruskal  | 0.022081 |
| 3. Sparse / Matrix / Prim  | 0.008800 |
| 4. Dense / Matrix / Prim   | 0.009991 |

빠른 순서는 Case 1 < Case 3 < Case 4 < Case 2임.

## 4. 비교 분석

### 4-1. 희소 그래프와 밀집 그래프의 성능 차이

간선이 6배(100 -> 600)로 늘었을 때의 변화:

| 방법                  | 시간                                | 메모리                         |
| --------------------- | ----------------------------------- | ------------------------------ |
| Kruskal + 인접 리스트 | 0.003502 -> 0.022081 ms (약 6.3배)  | 5788 -> 27788 Bytes (약 4.8배) |
| Prim + 인접 행렬      | 0.008800 -> 0.009991 ms (약 1.14배) | 11038 Bytes 그대로             |

Kruskal과 인접 리스트는 간선 수 E에 비례해 커지고, Prim과 인접 행렬은 정점 수 V에만 의존함. 그래서 밀도의 영향이 크게 다르게 나타남.

### 4-2. 인접 리스트와 인접 행렬의 메모리 사용 차이

- **인접 행렬**
  - 간선 수와 관계없이 V x V = 10000 Bytes를 사용함.
  - 희소 그래프에서는 2500칸 중 200칸(8%)만 쓰이고 나머지는 0으로 낭비됨. 밀집 그래프에서는 1200칸(48%)이 쓰임.
- **인접 리스트**
  - 실제 간선 수만큼만 노드를 만들지만, 노드마다 next 포인터가 더 붙어 E에 비례해 커짐.
  - 희소 그래프에서는 3600 Bytes로 행렬보다 약 2.8배 작음. 밀집 그래프에서는 19600 Bytes로 행렬보다 약 2배 큼.
- **손익분기점**
  - 그래프 표현만 비교하면 400 + 32E = 10000에서 E = 300임 (식으로 계산한 값).
- **보조 자료구조**
  - Prim은 450 Bytes로 고정임.
  - Kruskal은 간선 배열 때문에 1600 -> 7600 Bytes로 커짐.

### 4-3. Kruskal과 Prim의 실행 특성 차이

- **Kruskal (간선 중심, O(E log E))**
  - 시간 대부분이 전체 간선 정렬임.
  - E가 6배가 되면 정렬량은 이론상 6 x log 600 / log 100 ≈ 8.3배가 됨. 실측은 6.3배였음.
  - 실측이 이론보다 작은 것은 보조 배열 할당·해제 같은 고정 비용이 양쪽에 똑같이 들어가기 때문으로 추정됨.
  - MST에 들어가는 간선은 49개뿐임. 희소 그래프에서는 전체 간선의 49%이지만, 밀집 그래프에서는 약 8%뿐임. 밀집 그래프에서는 정렬한 간선 대부분이 MST에 쓰이지 않는 셈임.
- **Prim (정점 중심, O(V²))**
  - 정점을 50번 선택하고, 매번 key 탐색 50칸과 행렬 행 갱신 50칸을 수행함. 약 5000단계로 간선 수와 무관함.
  - 밀집 그래프에서는 key 갱신이 늘어나는 정도라 시간이 약 1.14배만 늘었음.

### 4-4. 그래프 밀도가 각 방법의 성능에 미치는 영향

| 비교                | 희소 (E=100)                       | 밀집 (E=600)                                  |
| ------------------- | ---------------------------------- | --------------------------------------------- |
| 더 빠른 쪽          | Kruskal (0.003502 ms)              | Prim (0.009991 ms)                            |
| 상대 속도           | Prim이 약 2.5배 느림               | Kruskal이 약 2.2배 느림                       |
| 메모리가 더 작은 쪽 | 인접 리스트 + Kruskal (5788 Bytes) | 인접 행렬 + Prim (11038 Bytes, 약 2.5배 작음) |

- **희소 그래프:** 정렬할 간선이 적은 Kruskal + 인접 리스트가 시간과 메모리 모두 유리했음. Prim은 대부분 0인 행렬까지 V²만큼 탐색해야 해서 불리했음.
- **밀집 그래프:** 간선 정렬과 간선 배열 때문에 Kruskal + 인접 리스트가 불리해짐. 간선 수의 영향을 거의 받지 않는 Prim + 인접 행렬이 유리해짐.
- **결론:** 희소 그래프에는 Kruskal + 인접 리스트, 밀집 그래프에는 Prim + 인접 행렬이 적합했음. 다만 실행시간이 역전되는 정확한 간선 수는 E=100과 600 사이라는 것까지만 알 수 있음. 중간 값은 측정하지 않았기 때문임.

## 5. 참고

- 실행시간의 절대값은 CPU, 컴파일 옵션, 다른 프로세스의 영향에 따라 달라질 수 있음. 비교할 때 의미가 있는 것은 빠른 순서와 증가 배율임.
- 메모리는 sizeof 기준의 요청 크기이므로 할당자 오버헤드를 포함한 실제 프로세스 메모리와는 다를 수 있음.
