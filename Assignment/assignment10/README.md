# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

선택 정렬, 버블 정렬(일반 / 조기 종료), 삽입 정렬(`>` / `>=`)을 C로 구현하고,
Key 1 비교 횟수와 데이터 이동 횟수, 정렬 안정성을 측정·분석함.

이 문서의 모든 수치는 기본 시드(20261027)로 실행한 실제 결과(`output.txt`)임.

---

./SortCompare            # 기본 시드 20261027 -> 항상 같은 결과

- 진행 상황(`random trials : 37 / 100`)은 표준 에러로 출력하므로 `./SortCompare > output.txt` 로 결과만 저장할 수 있음.

## 2. 프로그램 구성

### 2.1 데이터 구조

```c
typedef struct {
    int key1;   /* 정렬 기준 키 (0 ~ 1,000,000) */
    int key2;   /* 보조 키 (0 ~ 1,000,000, 정렬 기준 아님) */
    int order;  /* 원래 입력 순서 (안정성 검증용, 정렬 기준 아님) */
} Data;
```

- 정렬은 `key1` 만으로 오름차순 수행함. `key2` 와 `order` 는 비교에 쓰지 않음.
- 구조체 전체를 대입하므로 두 키는 항상 하나의 데이터로 함께 이동함.
- 난수는 `rand()` 대신 xorshift32를 직접 구현함. 왜냐하면 Windows의 `rand()` 는 최댓값이 32,767이라 0 ~ 1,000,000을 표현할 수 없고, 직접 구현하면 운영체제와 관계없이 같은 시드에서 같은 데이터가 나오기 때문임.

### 2.2 주요 함수

| 함수                                    | 역할                                                               |
| --------------------------------------- | ------------------------------------------------------------------ |
| `selection_sort`                        | 선택 정렬                                                          |
| `bubble_sort`                           | 일반 버블 정렬 (n-1번 순회를 모두 수행)                            |
| `bubble_sort_early`                     | 조기 종료 버블 정렬 (교환 없는 순회가 나오면 종료)                 |
| `insertion_sort(a, n, allow_equal, st)` | 삽입 정렬. `allow_equal=0` 이면 Case A(`>`), `1` 이면 Case B(`>=`) |
| `run_sort`                              | 입력을 복사해 정렬하고, 결과 검증과 안정성 위반 수를 계산          |
| `is_valid_result`                       | 정렬 결과가 올바른지 검증 (2.3 참고)                               |
| `count_stability_violations`            | Key 1이 같은 인접 쌍 중 원래 순서가 뒤집힌 쌍의 수                 |
| `count_inversions`                      | 역순쌍 수 (i < j 인데 key1[i] > key1[j] 인 쌍)                     |

### 2.3 정렬 결과 검증

전체 10,000개를 출력하지 않는 대신, 모든 정렬 실행 후 `is_valid_result` 로 다음 세 가지를 확인함.

1. Key 1이 오름차순인가
2. `order` 로 입력 데이터의 원래 위치를 찾았을 때 `key1`, `key2` 가 모두 같은가 (두 키가 함께 이동했는가)
3. `order` 가 중복되거나 빠진 것이 없는가 (데이터 손실·복제가 없는가)

모든 실험(무작위 100회 × 5종, 상태별, 안정성, 추가 분석)에서 **PASS** 함.

## 3. 측정 기준

### 3.1 비교 횟수

- 두 데이터의 `key1` 을 비교하기 **직전**에 `comparisons++` 를 수행함. 따라서 비교 결과와 관계없이 실제 수행한 비교가 모두 기록됨.
- 반복 조건(`j < n - 1 - i`), 인덱스 검사(`j >= 0`), 선택 정렬의 `min != i` 는 인덱스 비교이므로 제외함.

### 3.2 이동 횟수

데이터(구조체) 하나를 통째로 대입할 때마다 `moves++` 를 수행함.

| 연산                                     | 이동 횟수 |
| ---------------------------------------- | --------- |
| 교환 (`temp = x; x = y; y = temp;`)      | 3         |
| 삽입 정렬 `current = a[i]`               | 1         |
| 삽입 정렬 한 칸 이동 `a[j + 1] = a[j]`   | 1         |
| 삽입 정렬 최종 대입 `a[j + 1] = current` | 1         |

### 3.3 측정에서 제외한 연산

- 데이터 생성, 각 정렬에 넘기는 입력 복사(`memcpy`)
- 시험 입력 준비(사전 정렬, 역순 만들기, 부분 교란). 사전 정렬은 라이브러리 `qsort` 를 쓰지 않고 직접 구현한 삽입 정렬로 수행한 뒤 횟수를 버림.
- 결과 검증, 역순쌍 계산

### 3.4 구현상 선택

- 선택 정렬은 최솟값이 이미 제자리(`min == i`)이면 교환을 생략함. 그래서 이미 정렬된 데이터에서 이동이 0회임.
- 삽입 정렬은 이동이 필요 없어도 `current` 저장과 최종 대입을 항상 수행함(과제 설명 그대로). 그래서 이미 정렬된 데이터에서도 이동이 2(n-1)회 발생함.

## 4. 무작위 데이터 100회 실험

### 4.1 실험 방법

1. 매 반복마다 새 무작위 데이터 10,000개를 생성함.
2. 같은 데이터의 복사본을 5개 정렬(선택, 버블, 버블 ET, 삽입 `>`, 삽입 `>=`)에 각각 넘김. 따라서 한 반복 안에서 모든 알고리즘은 같은 입력을 받음.
3. 비교·이동 횟수를 누적하고 결과를 검증함.
4. 100회 반복 후 총합과 평균을 계산함.

삽입 정렬 비교가 이론값보다 평균 8.66회 적은 이유는, 새로 들어온 데이터가 앞의 모든 데이터보다 작으면 `j >= 0` 조건으로 반복이 끝나서 "멈추는 비교" 1회가 생기지 않기 때문임. 이런 일은 무작위 배열에서 평균 약 H(n) - 1 = 8.79회 일어나므로 실측과 거의 같음.

### 4.4 분석

- **선택·버블 정렬의 비교 횟수는 100회 모두 49,995,000으로 고정**됨. 왜냐하면 두 알고리즘 모두 데이터가 어떻게 생겼든 정해진 범위를 끝까지 비교하기 때문임.
- **삽입 정렬은 비교가 약 절반(50.05%)** 임. 왜냐하면 삽입 정렬은 자기보다 큰 데이터만 지나가고 멈추는데, 무작위 데이터에서 앞쪽에 있는 큰 데이터의 수(역순쌍)가 평균적으로 전체 쌍의 절반이기 때문임.
- **이동 횟수는 선택 정렬이 압도적으로 적음**(29,971회 = 평균 9,990번 교환). 왜냐하면 선택 정렬은 위치 하나당 최대 한 번만 교환하므로 이동이 최대 3(n-1) = 29,997회를 넘지 않기 때문임.
- **버블 정렬 이동은 삽입 정렬의 약 3배**(2.998배)임. 두 알고리즘 모두 인접한 역순쌍을 하나씩 해소하지만, 버블은 한 번에 교환(이동 3회)을 쓰고 삽입은 한 칸 이동(이동 1회)을 쓰기 때문임.

## 5. 버블 정렬의 조기 종료 조건

### 5.1 구현

```c
for (int i = 0; i < n - 1; i++) {
    int swapped = 0;
    for (int j = 0; j < n - 1 - i; j++) {
        st->comparisons++;
        if (a[j].key1 > a[j + 1].key1) {
            swap_data(&a[j], &a[j + 1], st);
            swapped = 1;
        }
    }
    if (!swapped) break;   /* 이번 순회에서 교환이 없으면 종료 */
}
```

조기 종료 여부 외의 조건(비교 연산자, 교환 방식, 순회 범위)은 일반 버블 정렬과 같음.

### 5.2 결과 (모든 입력 상태)

| 입력                       | 일반 버블 비교 | 조기 종료 비교 | 조기 종료 순회 수 | 비교 절감률 |
| -------------------------- | -------------: | -------------: | ----------------: | ----------: |
| 무작위 (100회 평균)        |     49,995,000 |     49,985,078 |          9,874.73 |       0.02% |
| 이미 정렬됨                |     49,995,000 |          9,999 |                 1 |      99.98% |
| 역순 정렬됨                |     49,995,000 |     49,995,000 |             9,999 |          0% |
| 부분 정렬 (무작위 교환)    |     49,995,000 |     49,845,669 |             9,453 |       0.30% |
| 부분 정렬 (블록 섞기) \*   |     49,995,000 |        199,790 |                20 |      99.60% |
| 부분 정렬 (뒤 10% 섞기) \* |     49,995,000 |      9,265,175 |               974 |      81.47% |

\* 8.3절 추가 분석 데이터. 일반 버블 정렬은 입력과 관계없이 항상 49,995,000회임.

**이동 횟수는 모든 입력에서 두 방식이 완전히 같음.** 왜냐하면 조기 종료는 "교환이 하나도 없는 순회"만 건너뛰므로 교환 자체는 하나도 줄지 않기 때문임.

### 5.3 분석

- **이미 정렬된 데이터**에서는 첫 순회에서 교환이 없으므로 9,999회 비교 후 바로 종료함. 효과가 가장 큼.
- **역순 데이터**에서는 마지막 순회까지 매번 교환이 일어나므로 조기 종료가 전혀 일어나지 않음.
- **무작위 데이터에서 효과가 거의 없음(0.02%)**. 평균 124번의 순회를 건너뛰었지만, 건너뛴 것은 비교가 가장 적은 마지막 순회들(각 1 ~ 124회 비교)이라 절감량이 작음.

조기 종료 순회 수를 결정하는 것은 **"작은 값이 왼쪽으로 얼마나 멀리 이동해야 하는가"** 임.

- 큰 값은 한 순회에서 오른쪽 끝까지 계속 밀려가므로 빨리 제자리를 찾음.
- 작은 값은 한 순회에 왼쪽으로 **한 칸**만 이동함.
- 따라서 필요한 순회 수 = (왼쪽으로 가장 멀리 가야 하는 데이터의 거리) + 1(교환 없음 확인)임.

블록 섞기는 모든 데이터가 블록(크기 20) 안에 있어 최대 19칸만 이동하면 되므로 정확히 20번 순회로 끝남. 반대로 무작위 교환은 작은 값 하나가 수천 칸 오른쪽으로 옮겨지는 경우가 생기고, 그 값 하나 때문에 9,453번 순회가 필요함.

## 6. 정렬 알고리즘의 안정성 검증

### 6.1 검증 방법

1. 각 데이터에 원래 입력 순서 `order` 를 저장함 (정렬 기준 아님).
2. Key 1만 기준으로 정렬함.
3. 정렬 결과에서 Key 1이 같은 **인접한 두 데이터**의 `order` 가 증가하는지 확인함. 감소하는 쌍이 하나라도 있으면 불안정(Unstable)으로 판정함.

정렬 후 같은 Key 1끼리는 연속으로 모이므로, 인접 쌍만 확인해도 같은 키 그룹 전체의 순서 유지 여부를 판정할 수 있음. 동시에 2.3절의 결과 검증도 수행해 정렬 자체가 올바른지 함께 확인함.

### 6.2 검증에 사용한 입력 데이터

| 시험   | 데이터                                                        | 같은 Key 1 인접 쌍 |
| ------ | ------------------------------------------------------------- | -----------------: |
| Test 1 | 과제 예시 4개: (527,100) (527,200) (125,300) (892,400)        |                  1 |
| Test 2 | 10,000개, Key 1을 0 ~ 99에서 생성 (키 하나당 평균 100개 중복) |              9,900 |
| Test 3 | 4절 무작위 100회 실험 데이터 (Key 1 0 ~ 1,000,000)            |    평균 49.41 / 회 |

무작위 데이터에서는 중복이 적으므로(이론 기대값 C(10000, 2) / 1,000,001 = 약 50쌍, 실측 49.41쌍) 중복이 많은 Test 2를 별도로 만들어 검증함.

### 6.3 결과

| 알고리즘              | Test 1   | Test 2 위반 쌍 | Test 3 위반 발생 | 최종 판정    |
| --------------------- | -------- | -------------: | ---------------: | ------------ |
| 선택 정렬             | Unstable |  3,270 / 9,900 |      100 / 100회 | **Unstable** |
| 버블 정렬             | Stable   |      0 / 9,900 |        0 / 100회 | **Stable**   |
| 버블 정렬 (조기 종료) | Stable   |      0 / 9,900 |        0 / 100회 | **Stable**   |
| 삽입 정렬 (`>`)       | Stable   |      0 / 9,900 |        0 / 100회 | **Stable**   |
| 삽입 정렬 (`>=`)      | Unstable |  9,900 / 9,900 |      100 / 100회 | **Unstable** |

Test 1 실제 출력:

```
Input                : (527,100) (527,200) (125,300) (892,400)
Selection Sort       : (125,300) (527,200) (527,100) (892,400) -> Unstable
Bubble Sort          : (125,300) (527,100) (527,200) (892,400) -> Stable
Bubble Sort (ET)     : (125,300) (527,100) (527,200) (892,400) -> Stable
Insertion Sort (>)   : (125,300) (527,100) (527,200) (892,400) -> Stable
Insertion Sort (>=)  : (125,300) (527,200) (527,100) (892,400) -> Unstable
```

### 6.4 선택 정렬 : 불안정

Test 1에서 실제로 일어난 과정:

```
i = 0 : 최솟값 (125,300) 은 index 2
        index 0 <-> index 2 교환
        [(527,100) (527,200) (125,300) (892,400)]
     -> [(125,300) (527,200) (527,100) (892,400)]
                               ^ (527,100) 이 (527,200) 을 건너뛰어 뒤로 감
```

원인: 선택 정렬은 **멀리 떨어진 두 데이터를 교환**함. 교환되는 데이터가 사이에 있는 같은 키 데이터를 건너뛰면 상대 순서가 뒤집힘. 이후 단계에서 이를 되돌리는 과정도 없음. Test 2에서는 같은 키 인접 쌍의 33.0%, Test 3에서는 33.7%가 뒤집혔고, 무작위 데이터 100회 중 100회 모두 위반이 발생함. 즉 중복이 50쌍 정도만 있어도 사실상 매번 불안정 결과가 나옴.

### 6.5 버블 정렬 : 안정 (일반 / 조기 종료 모두)

원인: 버블 정렬은 **인접한 두 데이터만** 교환하고, 교환 조건이 `>`(엄격히 클 때)임. 같은 키 두 데이터는 교환되지 않으므로 서로를 건너뛸 방법이 없음. 조기 종료는 순회를 일찍 끝낼 뿐 교환 규칙은 같으므로 역시 안정임.
(참고: 교환 조건을 `>=` 로 바꾸면 같은 키도 교환하므로 버블 정렬도 불안정해짐.)

### 6.6 삽입 정렬 : `>` 는 안정, `>=` 는 불안정

```c
Case A : need_shift = (a[j].key1 >  current.key1);   /* 같은 키에서 멈춤 */
Case B : need_shift = (a[j].key1 >= current.key1);   /* 같은 키도 밀어냄 */
```

Test 1에서 `i = 1`, `current = (527,200)` 일 때:

|               | `a[0] = (527,100)` 비교      | 결과                               |
| ------------- | ---------------------------- | ---------------------------------- |
| Case A (`>`)  | 527 > 527 거짓 -> 멈춤       | (527,100) (527,200) -> 순서 유지   |
| Case B (`>=`) | 527 >= 527 참 -> 뒤로 밀어냄 | (527,200) (527,100) -> 순서 뒤집힘 |

원인:

- **Case A** 는 같은 키를 만나면 멈추므로, 새 데이터가 항상 기존 같은 키 데이터의 **뒤**에 들어감. 그래서 입력 순서가 유지됨.
- **Case B** 는 같은 키도 밀어내므로, 새 데이터가 기존 같은 키 데이터들의 **앞**으로 들어감. 이것이 반복되면 같은 키 그룹의 순서가 **완전히 역순**이 됨. 실제로 위반 쌍 수가 같은 키 인접 쌍 수와 정확히 같음(Test 2: 9,900 / 9,900, Test 3: 4,941 / 4,941).

### 6.7 `>=` 의 추가 비용 (Test 2)

|                  |  비교 횟수 |  이동 횟수 |
| ---------------- | ---------: | ---------: |
| 삽입 정렬 (`>`)  | 24,569,683 | 24,579,687 |
| 삽입 정렬 (`>=`) | 25,069,655 | 25,079,746 |
| 차이             |   +499,972 |   +500,059 |

`>=` 는 안정성을 잃을 뿐 아니라 일도 더 많이 함(약 2.0% 증가). 같은 키를 가진 데이터 쌍마다 불필요한 한 칸 이동이 한 번씩 추가되기 때문임. 따라서 추가된 이동 500,059회는 Test 2에서 Key 1이 같은 데이터 쌍의 수와 같으며, 이론 기댓값 C(10000, 2) / 100 = 499,950 과 거의 같음.

### 7.4 이미 정렬된 데이터

- **선택 정렬**: 비교 49,995,000회 그대로, 이동 0회. 왜냐하면 매번 최솟값을 찾기 위해 나머지를 끝까지 비교해야 하지만, 찾은 최솟값이 항상 제자리라 교환이 생략되기 때문임.
- **일반 버블 정렬**: 비교 49,995,000회 그대로, 이동 0회. 교환은 없지만 정해진 순회를 모두 수행함.
- **조기 종료 버블 정렬**: 비교 9,999회(1번 순회), 이동 0회. 첫 순회에서 교환이 없어 바로 종료함.
- **삽입 정렬**: 비교 9,999회, 이동 19,998회. 각 데이터가 바로 앞 데이터와 1번만 비교하고 멈춤. 이동은 `current` 저장과 최종 대입이 매번 일어나서 2 × 9,999 = 19,998회임. 이 두 대입은 이동이 없을 때 생략하도록 바꿀 수 있지만, 이번 과제에서는 과제 설명대로 그대로 계산함.

### 7.5 역순으로 정렬된 데이터 (최악의 경우)

- **버블 정렬(두 방식 모두)**: 비교 49,995,000회, 이동 149,984,841회 = 3 × 49,994,947(역순쌍). 거의 모든 쌍을 교환해야 하므로 가장 느림. 매 순회에 교환이 있어서 조기 종료가 일어나지 않음.
- **삽입 정렬**: 비교 49,995,000회, 이동 50,014,945회 = 역순쌍 + 2(n-1). 새 데이터가 매번 맨 앞까지 가야 함. 그래도 이동은 버블의 1/3 수준임.
- **선택 정렬**: 비교는 같고 이동 15,078회(교환 5,026번). 역순에서는 한 번 교환할 때 앞쪽과 뒤쪽 두 데이터가 동시에 제자리를 찾으므로 교환이 약 n/2 = 5,000번이면 됨. 그래서 무작위(교환 약 9,990번)보다 이동이 오히려 적음.

### 7.6 일부 정렬된 데이터

- **삽입 정렬이 가장 큰 이득을 봄**: 비교 3,025,600회로 무작위의 12.1%임. 비교·이동이 역순쌍 수(3,015,605)에 비례하기 때문임.
- **선택 정렬**: 비교는 그대로, 이동은 1,506회(교환 502번). 제자리를 벗어난 데이터만 교환하므로 이동은 매우 적음.
- **일반 버블 정렬**: 비교는 그대로, 이동은 3 × 역순쌍 = 9,046,815회.
- **조기 종료 버블 정렬**: 비교가 0.30%만 줄어듦. 5.3절에서 설명했듯이, 멀리 오른쪽으로 옮겨진 작은 값 하나 때문에 9,453번 순회가 필요하기 때문임. "대부분 정렬되어 있다"는 사실만으로는 조기 종료가 효과를 보장하지 못함.

## 8. 부분 정렬 데이터 생성 방법 및 AI 활용

### 8.1 AI 활용 내용

AI(Claude)에게 부분 정렬 데이터를 만드는 방법을 질문하여 다음 내용을 조사함.

- 생성 방법 후보 3가지와 특징
  1. **무작위 위치 쌍 교환**: 정렬된 데이터에서 무작위 두 위치를 k번 교환. 일부 데이터가 멀리 이동할 수 있음.
  2. **블록 내부 섞기**: 데이터를 일정 크기 블록으로 나누고 블록 안에서만 섞음. 모든 데이터가 제자리 근처에 머묾.
  3. **일정 구간만 섞기**: 앞부분은 정렬을 유지하고 뒤쪽 일부 구간만 섞음.
- 정렬된 정도를 수치로 나타내는 기준
  - **제자리에 있지 않은 데이터 비율**
  - **역순쌍(Inversion) 수**: 삽입 정렬의 이동 횟수, 버블 정렬의 교환 횟수와 직접 연결되는 지표

### 8.2 본 실험에서 사용한 방법

**정렬된 데이터에서 무작위로 고른 두 위치의 데이터를 교환하는 작업을 N의 5%인 500회 수행함.**

| 기준                      | 값                                        |
| ------------------------- | ----------------------------------------- |
| 교환 횟수                 | 500회 (N의 5%)                            |
| 제자리에 있지 않은 데이터 | 946 / 10,000개 (9.46%) -> 약 90%는 제자리 |
| 역순쌍 수                 | 3,015,605 (최대의 6.03%)                  |

이 방법을 선택한 이유는 과제 예시와 가장 가깝고, 교환 횟수 하나로 정렬 정도를 조절할 수 있으며, 데이터가 멀리 이동하는 경우를 포함해 버블 정렬의 약점을 확인할 수 있기 때문임. 교환 후보가 겹치거나 같은 위치가 뽑힐 수 있어서 제자리를 벗어난 데이터는 최대 1,000개가 아닌 946개임.

### 8.3 추가 분석 : 생성 방법에 따른 차이

같은 정렬 데이터에서 세 가지 방법으로 만든 입력을 비교함.

| 방법                |    역순쌍 | 제자리 아님 | 버블 ET 비교 | 버블 ET 순회 | 삽입 비교 | 삽입 이동 |
| ------------------- | --------: | ----------: | -----------: | -----------: | --------: | --------: |
| 무작위 교환 (5%)    | 3,015,605 |         946 |   49,845,669 |        9,453 | 3,025,600 | 3,035,603 |
| 블록 섞기 (크기 20) |    47,815 |       9,520 |      199,790 |           20 |    57,812 |    67,813 |
| 뒤 10% 섞기         |   244,390 |       1,000 |    9,265,175 |          974 |   254,389 |   264,388 |

- **블록 섞기는 95.2%가 제자리를 벗어났는데도 가장 빠름.** 모든 데이터가 최대 19칸 안에 있기 때문임.
- **무작위 교환은 9.46%만 벗어났는데도 버블 ET에게 가장 느림.** 일부 데이터가 아주 멀리 이동했기 때문임.
- 따라서 "몇 개가 제자리를 벗어났는가"보다 **"얼마나 멀리 벗어났는가"(역순쌍 수, 최대 이동 거리)** 가 성능을 결정함.
- 삽입 정렬은 세 경우 모두 비교 = 역순쌍 + 약 (n-1), 이동 = 역순쌍 + 2(n-1)로 역순쌍을 정확히 따라감.
- 뒤 10% 섞기는 정렬할 부분이 1,000개뿐인데도 버블 ET가 9,265,175회 비교함. 매 순회마다 이미 정렬된 앞부분 9,000개도 처음부터 다시 비교하기 때문임.

## 9. 종합 분석

### 9.1 초기 정렬 상태가 각 알고리즘에 미치는 영향

| 알고리즘              | 비교 횟수           | 이동 횟수                 | 입력 상태 영향                           |
| --------------------- | ------------------- | ------------------------- | ---------------------------------------- |
| 선택 정렬             | 항상 n(n-1)/2       | 3 × 교환 수 (최대 3(n-1)) | 비교는 영향 없음. 이동만 약간 변함       |
| 버블 정렬             | 항상 n(n-1)/2       | 3 × 역순쌍                | 비교는 영향 없음. 이동은 역순쌍에 비례   |
| 버블 정렬 (조기 종료) | 순회 수에 따라 변함 | 3 × 역순쌍                | 이미 정렬·제자리 근처 교란에서만 큰 효과 |
| 삽입 정렬             | 약 역순쌍 + (n-1)   | 역순쌍 + 2(n-1)           | 정렬 정도에 가장 민감하게 반응           |

### 9.2 성능 차이가 발생하는 원인

1. **"이미 정렬되어 있음"을 알아차리는가**
   선택 정렬과 일반 버블 정렬은 입력과 관계없이 정해진 비교를 모두 수행하므로 비교 횟수가 항상 49,995,000회임. 삽입 정렬은 데이터마다 제자리를 찾으면 바로 멈추고, 조기 종료 버블 정렬은 순회 단위로만 멈출 수 있음. 그래서 정렬된 데이터에서 9,999회로 줄어드는 것은 이 둘뿐임.

2. **한 번의 작업으로 해결하는 무질서의 양**
   버블 정렬의 교환과 삽입 정렬의 한 칸 이동은 역순쌍을 정확히 1개씩 해소함. 그래서 두 알고리즘의 작업량은 역순쌍 수에 비례하며, 실측값이 이론식과 정확히 일치함. 선택 정렬의 교환은 데이터 하나를 최종 위치로 바로 보내 여러 역순쌍을 한 번에 해소함. 그래서 이동 횟수가 가장 적음.

3. **작업 한 번의 비용**
   역순쌍 하나를 해소하는 데 버블 정렬은 이동 3회(교환), 삽입 정렬은 이동 1회(한 칸 이동)를 씀. 그래서 무작위 데이터에서 버블 정렬의 이동은 삽입 정렬의 2.998배임.

4. **데이터가 움직이는 방향의 비대칭 (버블 정렬)**
   큰 값은 한 순회에 끝까지 이동하지만 작은 값은 한 칸씩만 이동함. 그래서 조기 종료 효과는 "가장 멀리 왼쪽으로 가야 하는 데이터"가 결정하며, 무작위·부분 교환 데이터에서는 효과가 거의 없음.

5. **안정성을 결정하는 것**
   멀리 떨어진 데이터를 교환하는 선택 정렬은 같은 키를 건너뛰므로 불안정함. 인접한 데이터만 다루면서 같은 키에서 멈추는(`>`) 버블·삽입 정렬은 안정함. 같은 알고리즘이라도 `>=` 를 쓰면 같은 키를 넘어가므로 불안정해지고 이동도 늘어남.

| 같은 키의 순서 유지가 필요한 경우 | 삽입 정렬(`>`) 또는 버블 정렬 | 모든 시험에서 위반 0                            |
| 일반적인 경우                     | 셋 중에서는 삽입 정렬         | 비교·이동 모두 버블보다 적고 안정적             |

버블 정렬은 세 알고리즘 중 이동 횟수가 가장 많고, 조기 종료를 넣어도 정렬된 데이터가 아니면 효과가 작아서 실용적인 장점이 가장 적었음.
